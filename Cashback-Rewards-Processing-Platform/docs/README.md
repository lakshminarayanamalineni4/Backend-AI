## Documentation conventions

Each **topic** document follows the same structure so you can study or skim consistently:

1. **Summary** — one-paragraph overview
2. **Definition** — precise terminology
3. **Why it matters** — connection to this project
4. **Core concepts** — tables, diagrams, and mental models
5. **Examples** — request/response or code tied to the cashback platform
6. **Common pitfalls** — mistakes to avoid in production systems
7. **Study checkpoints** — questions to verify understanding
8. **Related topics** — links to prerequisites and follow-ups
